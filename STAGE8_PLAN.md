# 💳 ЭТАП 8: Платежные системы

## 🎯 Цель:
Интегрировать онлайн оплату услуг через ЮKassa (или Stripe как альтернативу), чтобы клиенты могли оплачивать записи онлайн.

---

## 🤔 Выбор платежной системы:

### ЮKassa (Яндекс.Касса) - рекомендую для РФ
**Плюсы:**
- ✅ Российская система, работает в РФ
- ✅ Низкие комиссии (2-3%)
- ✅ Поддержка карт, СБП, электронных кошельков
- ✅ Простая интеграция
- ✅ Хорошая документация на русском

**Минусы:**
- ❌ Требуется юр.лицо/ИП для подключения
- ❌ Только для российского бизнеса

### Stripe - альтернатива (международная)
**Плюсы:**
- ✅ Международная система
- ✅ Отличная документация и API
- ✅ Работает во многих странах

**Минусы:**
- ❌ Сложности с подключением из РФ
- ❌ Более высокие комиссии
- ❌ Санкции

---

## 💡 Решение:

Реализуем **ЮKassa**, но с возможностью легко переключиться на Stripe.

Для тестирования будем использовать:
- **Тестовый режим** ЮKassa (не требует реального магазина)
- **Mock платежи** (имитация для разработки)

---

## 🔐 Что реализуем:

### Backend (6 компонентов):

1. **Обновление модели Payment в Prisma**
   - Связь с Booking
   - Поля: amount, status, paymentMethod, providerPaymentId

2. **Конфигурация платежной системы**
   - `server/src/config/payment.ts`
   - API ключи, настройки ЮKassa

3. **Сервис для работы с платежами**
   - `server/src/services/paymentService.ts`
   - Создание платежа
   - Проверка статуса
   - Обработка callback от ЮKassa

4. **Контроллер для платежей**
   - `server/src/controllers/paymentsController.ts`
   - Создание платежа
   - Webhook для подтверждения
   - Получение статуса

5. **Роуты для платежей**
   - `server/src/routes/payments.ts`
   - POST `/api/payments/create` - Создать платеж
   - POST `/api/payments/webhook` - Webhook от ЮKassa
   - GET `/api/payments/:id` - Статус платежа

6. **Обновление bookingsController**
   - Создание Payment записи при создании Booking
   - Проверка оплаты перед подтверждением

---

### Frontend (6 компонентов):

1. **API клиент для платежей**
   - `client/src/shared/api/paymentsApi.ts`
   - Создание платежа
   - Проверка статуса

2. **Страница оплаты**
   - `client/app/payment/[id]/page.tsx`
   - Выбор способа оплаты
   - Редирект на ЮKassa

3. **Страница успешной оплаты**
   - `client/app/payment/success/page.tsx`
   - Подтверждение оплаты

4. **Страница неудачной оплаты**
   - `client/app/payment/failure/page.tsx`
   - Информация об ошибке

5. **Обновление BookingForm**
   - Редирект на страницу оплаты после создания записи
   - Кнопка "Оплатить"

6. **Обновление ProfilePage**
   - Показ статуса оплаты записей
   - Кнопка "Оплатить" для неоплаченных

## 🔄 Процесс оплаты:

```
1. Клиент создает запись
   ↓
2. Backend создает Booking + Payment (status: PENDING)
   ↓
3. Frontend редиректит на страницу оплаты
   ↓
4. Клиент выбирает способ оплаты
   ↓
5. Backend создает платеж в ЮKassa
   ↓
6. ЮKassa возвращает payment_url
   ↓
7. Frontend редиректит на payment_url
   ↓
8. Клиент оплачивает на сайте ЮKassa
   ↓
9. ЮKassa отправляет webhook на наш сервер
   ↓
10. Backend обновляет Payment.status → PAID
    ↓
11. Backend обновляет Booking.status → CONFIRMED
    ↓
12. ЮKassa редиректит клиента на /payment/success
```

## 🧪 Режимы работы:

### 1. Mock режим (для разработки, БЕЗ реального подключения)
```typescript
// .env
PAYMENT_MODE=mock
```
- Платежи имитируются
- Автоматическое подтверждение через 3 секунды
- Не требует ключей ЮKassa
- **Используем ЭТО для разработки!**

### 2. Тестовый режим ЮKassa (с тестовыми ключами)
```typescript
// .env
PAYMENT_MODE=test
YUKASSA_SHOP_ID=test_shop_id
YUKASSA_SECRET_KEY=test_secret_key
```
- Реальная интеграция, но с тестовыми деньгами
- Требует регистрации в ЮKassa (бесплатно)
- Тестовые карты для проверки

### 3. Production режим (с реальными ключами)
```typescript
// .env
PAYMENT_MODE=production
YUKASSA_SHOP_ID=real_shop_id
YUKASSA_SECRET_KEY=real_secret_key
```
- Реальные платежи
- Требует настоящий магазин в ЮKassa
- Комиссии

## 💻 Обновления Prisma Schema:

```prisma
model Payment {
  id                Int           @id @default(autoincrement())
  bookingId         Int           @unique
  booking           Booking       @relation(fields: [bookingId], references: [id])
  
  amount            Int           // Сумма в копейках (1500 = 15.00 руб)
  status            PaymentStatus @default(PENDING)
  paymentMethod     String?       // card, sbp, wallet, etc
  
  providerPaymentId String?       // ID платежа в ЮKassa
  paymentUrl        String?       // URL для оплаты
  
  createdAt         DateTime      @default(now())
  updatedAt         DateTime      @updatedAt
  paidAt            DateTime?
}

enum PaymentStatus {
  PENDING      // Ожидает оплаты
  PROCESSING   // В процессе
  PAID         // Оплачен
  FAILED       // Ошибка
  REFUNDED     // Возврат
}
```

## 🔐 Безопасность:

1. **Webhook проверка**
   - Проверка подписи от ЮKassa
   - Защита от подделки уведомлений

2. **Idempotency**
   - Предотвращение дублирования платежей
   - Использование уникальных ключей

3. **Валидация сумм**
   - Проверка соответствия суммы платежа и записи
   - Защита от изменения цен на фронте

4. **Защита от повторной оплаты**
   - Проверка статуса перед созданием платежа
   - Блокировка уже оплаченных записей
